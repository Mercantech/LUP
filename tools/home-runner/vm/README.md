# Hjem.exe på en KVM-vært

VMM-imaget kører en Ubuntu 24.04-gæst med QEMU og KVM. Dockerfilen kontrollerer Canonicals signatur på checksumlisten og validerer Ubuntu-imaget mod den signerede liste. Gæsten bruger sit eget persistente qcow2-drev og kører gVisor inde i Linux-gæsten.

Værten skal give den uprivilegerede QEMU-proces skrive- og læseadgang til `/dev/kvm` via enhedens gruppe. Gæsten har 2 vCPU'er og 4 GiB RAM. Sæt VMM-containerens cgroup-grænse til 2 CPU'er og 5,5 GiB RAM. Brug en tom, dedikeret Docker-volume på `/vm` med automatisk kopiering af volume-markøren fra imaget. VMM-containeren bruger read-only root, `--cap-drop ALL`, `no-new-privileges` og en lille skrivbar tmpfs på `/tmp`. Montér kun KVM-enheden og gæstens eget drev.

På første boot leverer NoCloud-konfigurationen `bootstrap.sh` til `/usr/local/sbin/lup-home-worker-bootstrap` og den offentlige, midlertidige RSA-nøgle til `/etc/lup-home-runner-handoff.pem`. Kør bootstrap som root med `LUP_HOME_WORKER_SLOTS=1`. Sæt kun `LUP_VM_BOOTSTRAP=1` og `LUP_VM_USER_DATA_B64` på bootstrapcontaineren. Brug et separat bridge-net med midlertidig egress til download af signerede pakker og de tre runtime-images. Bootstrap sender den krypterede engangsoverdragelse og TLS-certifikatets fingeraftryk efter kodeworkertestene.

Sluk bootstrapgæsten via QMP, og start VMM-containeren med samme volume på det interne net `lup-home-runner-control`. Brug alias `lup-home-worker` og `unless-stopped` som genstartspolitik. QEMU starter nu med begrænset SLIRP og videresender port 8443 til gæstens TLS-proxy. Tilslut API'et til det interne net, og brug `https://lup-home-worker:8443` som worker-URL. Workerens nøgle opbevares af Dokploy, og API'et validerer gæstens TLS-certifikat med fingeraftrykket. Fjern bootstrapnettet, når gæsten er flyttet.
